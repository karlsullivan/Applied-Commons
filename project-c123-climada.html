Free, open-source (GPL-3.0, 479 stars) software framework for climate risk assessment and adaptation-option appraisal (CLIMADA-project, ETH Zurich). Quantifies hazard impact and compares adaptation measures, supporting the brief's documented benefit-cost (BCR) requirement for coastal and climate adaptation. Climate-independent software, runs year-round in cold or warm regions.

Known gaps

What the original design does not document:

  • No upstream-published minimum hardware spec (CPU cores / RAM / disk) for a single working unit; the compute-host item is an estimate from dataset sizes, not a documented requirement.
  • No published price for the compute host or internet service, so total_cost cannot be computed from upstream figures (only the free software/data/service components are priced, at $0).
  • Data API v2 docs (as retrieved) show no authentication/keys, but rate limits, quotas, availability SLAs, and data retention/versioning/expiry policies are not documented - an institutional or long-running deployment should confirm these directly with ETH/IAC.
  • Exact dataset sizes beyond LitPop (global ~0.7 GB) and one global TC scenario (~2.0 GB) are not enumerated per country/hazard in the retrieved listings, so disk planning is approximate.
  • The conda-forge binary build pins python 3.11 and exact dep versions (climada 6.2.0) while the main-branch pyproject lists a looser dev range (>=3.10,<3.13); a from-source build may need a slightly different toolchain than the binary packages.
  • No hardware/hosting spec: minimum CPU/RAM/disk, GPU use, or cloud-service recommendation is not documented anywhere in the docs or repos; all sizing in this pack is an estimate.
  • Flagship coastal-flood data not published: 'aqueduct_coastal_flood' (global probabilistic coastal flood maps ~1 km, 2/5/10/25/50/100/250/500-yr) and the 'ssp_population' exposure are named as supported in climada.conf and have data-type metadata on the API, but appear in 0 of the 8,667 live datasets, so a coastal-flood build cannot pull them as documented.
  • No coastal-flood / sea-level tutorial: doc-tree hazard tutorials cover Hail, StormEurope and TropicalCyclone only; coastal method must be assembled from Petals TC_Surge/coast modules plus the data types.
  • Two repos have no LICENSE file: climada_papers and learn-climada report no detected SPDX licence; code repos are clearly GPL-3.0 but publication/teaching content licensing is undocumented.
  • Version drift: readthedocs 'latest' shows 6.2.1-dev while the published release and the inspected commit are 6.2.0; no doc pin clarifies which docs version matches a given release.
  • Offline operation only partial: only the tropical-cyclone demo hazard+exposure ship in the package; all other hazards require the network Data API, but the deployment docs do not call out which hazards are offline-capable.
  • Dataset listing pagination is undocumented in the OpenAPI spec: the default listing is capped and requires ?limit= (used up to 50000) to retrieve all 8,667 datasets.
  • Upstream publishes no fixed baseline data checksum/hash for a reproducible end-to-end BCR, so there are no upstream 'expected value' targets; the running-instance check was validated against the bundled demo's own computed values instead.
  • No hardware sizing / RAM guidance for high-resolution (site-specific) runs - OOM risk is only documented in the issue tracker.
  • No offline mode for non-demo hazards: only the tropical-cyclone demo hazard + exposure ship in-package; every other hazard type needs the ETH Data API (network).
  • The cost_ben_ratio attribute is named as if it were cost/benefit but the tutorial's printed 'Benefit/Cost' column is its reciprocal - this definitional trap is not called out in the docs and must be inverted before comparing to the brief's benefit-cost ratio (2-10).
  • The published make install/unit/integ_test standards were not executed in this run (they need the repo checkout and, for integ, open internet); the running-instance verification was done on the installed package's bundled demo instead.

Safety

Pure-software build pack; fabricates no physical product, so no battery, gas-combustion, pressure, structural, water-food, chemical, mechanical, biological-medical or radio hazards. The only physical risk is operating a generic mains-powered compute host (low electrical + low heat-fire), for which the pack publishes no hardware/electrical/thermal guidance. Safe with standard IT-equipment controls, which the pack does not already cover.

HazardSeverityControls
The compute host draws mains power; shock risk from the power supply unit or a damaged power lead during setup/maintenance in homes, farms and villages, typically without an electrician present.lowUse a commercial host carrying a conformity mark (CE / UL / cUL) against IEC 62368-1; Use the intact OEM power lead; replace only with a correctly rated, certified lead; Do not open the PSU or rewire the host internally; on any power-supply fault, replace the unit; Any permanent/fixed mains connection is a qualified-person (electrician) step outside this pack, per IEC 60364 / national wiring codes
Sustained CPU load (CLIMADA is CPU-bound: dask / numba / pathos parallel impact calculation) can drive the host toward its thermal limit; in a confined or combustible space with blocked vents this risks overheating, component damage and, in an extreme case, fire.lowProvide ventilation clearance per the host OEM spec; never block intake or exhaust vents; Place the unit on a hard, non-flammable surface away from combustible material; Rely on thermal shutdown; power down if the unit becomes abnormally hot or starts to shut itself off; Do not run unattended at full load in a closed, fire-loaded room (e.g. a barn or shed)

Evidence

The strongest findings from Applied Commons research on this project:

  • CLIMADA's core tropical-cyclone hazard (climada_python) models WIND only (Holland 2008 / Emanuel parametric wind fields from IBTrACS tracks); it has no physical storm-surge component. The 2019 GMD platform paper lists coupled rainfall+surge modelling as explicit future work.
  • Storm surge in CLIMADA is an optional add-on in the separate climada_petals package with two implementations: TCSurgeBathtub, a crude linear wind-to-surge proxy (surge[m] = 0.1023*(v-26.82)+1.8288, Xu 2010/SLOSH-based, 0.2 m/km inland decay per Pielke 1997), and TCSurgeGeoClaw, a full 2D shallow-water flow solver (up to ~270 m resolution, HPC-scale, Linux/Mac only).
  • Wind-based TC economic-damage calibration (Eberenz et al. 2021, NHESS; 473 EM-DAT matched events, 1980-2017, 53 countries): the uncalibrated default impact function biases damage by up to a factor of 36 (N-W Pacific overestimation) and factor 5 (S Indian Ocean underestimation); regional calibration brings total damage ratios to ~1 per region, but single-event damage ratios still span several orders of magnitude (post-calibration RMSF ~6-36). The authors conclude the setup is 'not suitable to represent single TC events adequately.'
  • Only tropical cyclone is runnable fully offline from bundled data. The climada 6.2.0 wheel ships the TC demo hazard (tc_fl_1990_2004.h5, Florida, IBTrACS 1990-2004, ~2500 centroids) and demo exposure (exp_demo_today.h5), and the 10-minute tutorial (TC hazard + demo exposure + Emanuel-USA impact function + ImpactCalc) completes an end-to-end impact/averted-damage calculation with no network. The wheel bundles these files and setup_climada_data() copies them into the local CLIMADA data directory at import time, so 'offline' holds from a fresh install.
  • CLIMADA outputs a directly usable per-measure benefit-cost ratio: CostBenefit.calc() returns per-measure cost, averted-damage benefit, and Benefit/Cost ratio (plus a per-measure dict, present and future scenarios, discount rates, and a combined-measures view).
  • CLIMADA contains NO physical mangrove/marsh attenuation or averted-damage function. Zero code hits for mangrove/marsh/vegetation across the full file trees of climada_python, climada_petals and climada_papers. The 'Mangrove' in the MeasureSet tutorial is a placeholder adaptation measure with an arbitrary flat hazard-intensity impact (e.g. -10), not a physical averted-damage model.
  • The GeoClaw flow solver that CLIMADA's TCSurgeGeoClaw wraps was validated (Vogt et al. 2024, Communications Earth & Environment) against satellite-based floodplain observations for a global set of 71 storms; the models overall have 'only moderate skill in reproducing the observed floodplains.' GeoClaw outperforms the two static (incl. wind->inundation/bathtub-style) approaches but over-predicts inundation (true-negative-rate 93% vs 97-99% for the static models), and a full-scale ocean model (GTSMM) reproduces tide-gauge hydrographs better than GeoClaw.
  • Because CLIMADA's TC damage is driven by wind speed only, surge- and rain-driven damage is absorbed implicitly into the calibrated wind-based impact function and is poorly represented for surge-dominated, low-wind events. The Philippines case study in Eberenz et al. 2021 shows Tropical Storm Ketsana (2009, flood/surge-driven, low wind) with an event-damage ratio of 0.002 (simulated damage >2 orders of magnitude below reported) and Typhoon Haiyan at 0.17.
