MQTT v5 over a local broker
Codeac-mqtt-iot-bus
Kinddata
StatusApproved
ApprovedOctober 2026
Used by20 modules

Publish/subscribe designed for unreliable networks and small microcontrollers: a full client with TLS fits a bare ESP32. Home Assistant is a native MQTT client, and with discovery messages any publishing module appears in the dashboard without per-module code. The security controls are broker settings that cost nothing per module and close the spoofing gap the verification found; the telemetry-only scope keeps actuation safety local and out of the bus.

Specification

MQTT v5.0 (OASIS Standard) between modules and a local broker in every deployment (for example Mosquitto on the site gateway); no cloud dependency, bridging to a remote broker optional. MQTT 3.1.1 clients (ISO/IEC 20922:2016) are also allowed, since some firmware supports only 3.1.1; they rely on the timestamp in every payload where v5 would use message expiry. Security, all broker configuration: TLS 1.2 or 1.3 on port 8883 with the broker certificate validated against the deployment's own CA (validation never disabled); anonymous access disabled; one username and password per module, no shared or default passwords (ETSI EN 303 645); a per-module ACL so a module publishes only under ac/<module-id>/# and subscribes only to what it needs. Client certificates (mutual TLS) optional. Modules with a radio placed on the EU market also meet the RED cybersecurity requirements (Delegated Regulation (EU) 2022/30, EN 18031-1). Topics: readings on ac/<module-id>/<metric> as UTF-8 JSON with value, SI unit and timestamp (ac-iso8601-timestamps); ac/<module-id>/status retained online/offline, the offline set by a Last Will so a dead module shows offline. QoS 1 for records that must not be lost (consumers deduplicate); QoS 0 allowed for frequent ambient readings; v5 clients set message expiry on state topics so stale values are not read as live. Home Assistant: each module publishes retained MQTT discovery config (homeassistant/<component>/<module-id>/<object>/config) with its status topic as the availability topic, so it appears, and shows offline, without per-module integration code. Scope: telemetry and dashboards. A module that acts on commands (valves, pumps, heaters) keeps its safety interlocks local and fails safe when messages stop; field control uses ac-modbus-control, and MQTT command topics need their own standard, assessed against IEC 62443, before any module relies on them.
