Open-source (GPL-3.0, 88 stars) Python framework that maps gross forest GHG emissions, gross carbon removals (sequestration) and net flux at 30 m resolution, 2001-2025, across all carbon pools; feeds the Global Forest Watch platform. Provides the open, auditable MRV layer for biological CDR at scale. Global coverage including boreal forest, so usable for carbon accounting in cold climates.

Evidence

The strongest findings from Applied Commons research on this project:

  • The concentrated RF_>20yr variance was caused by a data error in the IPCC Tier 1 temperate >20-yr removal factors, not by genuine process uncertainty. The original model applied IPCC Table 4.9 values that carried implausibly large standard deviations - temperate mountain forest >20 yr was 4.4 t AGB ha-1 yr-1 +/- 100.7 (i.e. >1000% relative), and temperate oceanic forest >20 yr was 9.1 +/- 20.2. Gibbs et al. 2025 state explicitly that 'the largest change to the uncertainty analysis in terms of input values was the corrected IPCC Tier 1 temperate forest removal factors, which the model applies across large areas of Eurasian and Canadian forests.'
  • The framework (wri/carbon-budget, GPL-3.0, default branch master, last push 2026-11-24) is a 'Global forest carbon flux framework' that 'spatially applies IPCC national greenhouse gas inventory rules (2016 guidelines) for forests', published in Harris et al. (2021, Nature Climate Change) and Gibbs et al. (2025, ESSD). It is a Dockerized Python + GDAL + PostgreSQL/PostGIS + C++ pipeline run via a master script or individual stage scripts.
  • The framework is explicitly documented to run WITHOUT AWS credentials: 'The framework can still be run without AWS credentials; inputs will be downloaded from s3 but outputs will not be uploaded to s3. In that case, outputs will only be stored locally.' And for a fully s3-independent run: 'you need all the basic input files for all tiles in the docker folder /usr/local/tiles/'. A -nu/--no-upload flag disables all S3 uploads.
  • Download logic is local-first, so pre-staged inputs mean S3 is never contacted: every download helper (s3_file_download, s3_folder_download, gfw_data_lake_download) first checks os.path.exists(<local file>) and returns if present before building any 'aws s3 cp' command. README: 'The framework looks for files locally before downloading them in order to reduce run time.'
  • Single-country / single-tile runs are a documented first-class path. Use -l/--tile-id-list to restrict to specific tiles (e.g. Madagascar = tiles 10S_040E, 10S_050E, 20S_040E), and -sp to limit to one processor 'for framework development or running on small-ish countries that use only a few tiles.' Local runs use docker-compose with a host folder mapped to /usr/local/tiles.
  • There is no concrete permanence/durability design in the GFW forest carbon flux framework. Full-text checks of the ESSD 2025 paper, the current GitHub README (wri/carbon-budget), and the GFW framework blog find zero occurrences of permanence, durability, reversal, re-release, or liability concepts; the framework is a spatially explicit IPCC AFOLU gain-loss inventory model, not a storage-persistence or credit-liability system.
  • The temporal design that prevents year-level permanence tracking: gross emissions are assigned to the specific year of tree cover loss (Hansen lossyear), while tree cover gain is reported in one interval (2000-2020) with no year assignment, removals are computed as an annualized average spread over the entire 2001-2025 model period, and for pixels with both loss and gain 'the order is unknown' (ESSD 2025). Consequently net flux per pixel is a single cumulative 2001-2025 number with no year resolution, and the published net-flux dataset must be divided by 23 to get an average annual value.
  • The +/- 49 GtCO2e/yr on global gross removals in Harris 2021 was dominated by a single input: the removal factor for forests >20 years old (RF_>20yr). In the original model's variance decomposition (Harris 2021 SI Table S1, global rows), RF_>20yr accounts for ~99% of the output variance of global gross removals and net GHG flux, while the 2000-AGB-based emission factor (EF) accounts for ~87% of the variance of gross emissions and tree-cover-loss area (AD_loss) ~16%. So the uncertainty was not a broad, irreducible 'as large as the signal' problem across all inputs - it was concentrated in one parameter set.
