# Contributing

Contribute useful technical work: prior-art research, designs, software, instrumentation, modelling, experiments, datasets, replication, documentation, or expert review. Well-documented failures are welcome.

## Make a contribution

1. Read the relevant project README and [SAFETY.md](SAFETY.md). For a substantial change, briefly describe the problem and proposed output in an issue or pull request before investing heavily.
2. Keep the change focused. Use [PROJECT.md](templates/PROJECT.md) for a new project and [EXPERIMENT.md](templates/EXPERIMENT.md) for a test; mark unknowns rather than inventing detail.
3. Include enough information to review or reproduce the work: sources, design versions, methods, data locations, results, and limitations. Separate measured results from assumptions and estimates.
4. Open a pull request explaining what changed, why it is useful, and how it was checked. Flag hazards and any expertise needed for review.

Prefer a small, usable output over extra process. Keep project records beside the work and link to large datasets rather than duplicating them. Explain unavailable evidence and publication restrictions.

## Attribution and licensing

Only submit material you have the right to contribute. Credit sources and identify third-party licences and any exceptions clearly.

Unless otherwise stated, contributed software follows [Licence.md](Licence.md) (GPL-3.0-or-later), hardware designs follow [Licence-Hardware.md](Licence-Hardware.md) (CERN-OHL-S-2.0), and documentation and other non-software materials follow [Licence-Docs.md](Licence-Docs.md) (CC BY-SA 4.0). By contributing you agree your contribution is released under these licences. Do not contribute material whose licence is incompatible with them (for example non-commercial material).
