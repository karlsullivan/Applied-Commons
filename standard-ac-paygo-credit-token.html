StatusApproved
ApprovedNovember 2026

Shared by at least the meter terminal, the token backend and the core-banking module, and no approved or pending standard covers a meter-credit/token interface. STS (IEC 62055-41) is the published international prepayment token standard, so it is the canonical format; OpenPAYGO is kept as a separately declared profile because solar home systems widely use it. Only OpenPAYGO-python is permissively licensed (MIT); nxt-sts is AGPL-3.0. AC's own software is GPL-3.0-or-later and publishes its source, and GPL-3.0 section 13 allows combination with AGPL-3.0 code, so an AGPL backend fits AC's share-alike licensing, provided its source is offered to network users. The interface stays cheap: a 20-digit string over SMS or QR rather than a proprietary card or API.

Specification

Canonical format: the IEC 62055-41:2018 STS token. The 20-digit numeric string is the decimal rendering of the STS token (token identifier date/time, class and subclass, a random field and the encrypted value payload); its exact bit layout is defined by IEC 62055-41 and must be re-checked against the full text before any field-level claim is published. It is generated server-side and entered at the meter. Carrier: the IEC 62055-51 one-way numeric token carrier (keypad entry from SMS, USSD or QR). Delivery over ac-mqtt-iot-bus is a non-standard application-layer transport above the standard (nearest analogue: the IEC 62055-52 two-way virtual carrier), documented as such. Separate profile: a device may instead use the OpenPAYGO Token scheme (EnAccess OpenPAYGO, MIT), common in solar home systems. It is a different, non-interoperable algorithm (SipHash-2-4, 16-byte secret, value in the last digits), not another rendering of an STS token. Each meter or device declares its scheme when provisioned, and the backend generates tokens only in that scheme; the two are never mixed behind one interface. Keys: the per-meter decoder key (STS) or device secret (OpenPAYGO) is a server-side input, carried only over TLS, never logged or stored in plaintext, and never embedded in or sent with the token. The account ID and the price or quantity per token are backend records, not token fields; the meter binds a token through its key. Timestamps per ac-iso8601-timestamps. A missed top-up does not cut supply abruptly: the meter firmware keeps a grace window. Licences: OpenPAYGO-python is MIT; the nxt-sts STS reference implementation is AGPL-3.0, whose network clause applies to a hosted token backend built on it.
