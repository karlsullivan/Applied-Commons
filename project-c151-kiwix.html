The safety review found hazards that need controls when building or using this design.

Open-source (GPL-3.0, 962-star kiwix-tools; 20+ years old, 10M+ users in 212+ countries) suite that brings free knowledge (Wikipedia, medical guides, educational videos, repair manuals and custom content) offline via downloadable ZIM files, readable on any low-cost device including a Raspberry Pi or a Wi-Fi hotspot, in 100+ languages. COLD-CLIMATE GROUNDED: the Kiwix site documents a school running entirely on a Kiwix Hotspot in the remote, high-altitude, long-freezing-winter region of Ladakh (India), and users working off-grid ('I work off grid and Kiwix allows me to keep access to my data at all times').

Failure modes

FailureEffectMitigation
Kiwix Reader v3.14.0 becomes unusable on a low-end Android tablet with a large modern ZIM (wikipedia_en_all_nopic_2025-08).App takes 30+ seconds to open; each typed search character blocks 30-45s; opening an article takes 30-60s; queries longer than 5 characters return no results. Older ZIM (2018) in the old app (3.6.0) loads in seconds, so the regression is version/ZIM-dependent.Apply the fix from PR #4426 (move search to the IO thread, fetch 20 results instead of 100 per keystroke, add 150ms debounce, keep the UI thread free) and/or use a smaller ZIM variant; confirm search responsiveness returns to a couple of seconds on the target device.
Transferring a large ZIM to an Android device over USB MTP is slow and buggy.MTP caps at ~37 MiB/s (about 30% of connection speed) and is unreliable for big files - an 115GB ZIM can take ~an hour and may corrupt in transfer.Use USB-debugging 'adb push' (reported ~33 MB/s, copied successfully) or a Wi-Fi file-explorer transfer (up to ~80 MiB/s in practice) instead of MTP; verify the received file size/checksum before importing.
ZIM-version / app-version mismatch (an old app cannot open a newer ZIM).Kiwix 3.6.0 cannot open the current ZIM format, and the old ZIM in the new app is still slow - the pairing of app and ZIM determines whether the deployment is usable.Pair a current Reader build with a current (or format-compatible) ZIM, and re-run the search/performance acceptance check on the actual deployment hardware after pairing; pin the known-good app+ZIM combination in the deployment notes.
The Play Store Kiwix APK is restricted to a couple of directories for ZIM storage.Users who put the ZIM elsewhere (a common field practice) cannot find it; the library picker does not show versions or dates, so the wrong/old ZIM can be loaded.Store the ZIM under the allowed path (e.g. /Android/media/org.kiwix.kiwixmobile/) or sideload the APK, which can read ZIMs from anywhere; check ZIM version/date in the direct download directory (lb.download.kiwix.org) rather than trusting the library picker.
Slow displays (e-ink) and very low-end devices degrade readability of the Reader.Feature requests flag e-ink support (and, by extension, animation-heavy UI on slow screens) as a usability gap for the cheapest target devices.On e-ink or slow devices, use the disable-animations setting (PR #5090) and a smaller/short-text ZIM; verify content is legible on the actual display type before field release.

Known gaps

What the original design does not document:

  • Kiwix does not document the exact NVMe SSD capacity or part number shipped in the retail Hotspot (only that it is NVMe and ~40x faster than microSD).
  • No upstream bill-of-materials / parts-list file exists for the Hotspot hardware — the retail unit is assembled in-house by Kiwix and no BOM is published in the open repos (libkiwix, kiwix-tools, offspot/base-image, offspot/kiwix-hotspot).
  • The 27W (5V/5A) power figure is from the Raspberry Pi 5 datasheet/spec, not from a Kiwix document; Kiwix does not publish a measured idle or 24-client power draw for the node.
  • No solar/battery sizing document from Kiwix for off-grid operation: the retail unit ships with a rechargeable RTC battery and a standard charger, but Kiwix does not sell a solar kit or publish watt-hours needed for all-day field operation.
  • Price/currency drift: live shop lists CHF 260/330; the 2025 launch blog states USD 319 (tax+shipping). No fixed USD conversion is published, so the USD total is approximate.
  • Feature phones are not directly supported (content is browser-based on a Wi-Fi hotspot); the input's need for feature-phone / SMS / voice access is only partially met.
  • Safety (last-mile multi-hazard early warning) and local-language agricultural-advisory content are not present in the standard retail content bundles; the 1,309-ZIM library covers 100+ languages but these specific last-mile topics are a documented gap for this need.
  • Assembly/test steps are implied (flash image, add ZIMs via ZIM Manager/Imager, verify in the browser at the hotspot) but Kiwix does not publish a step-by-step BOM-style assembly+acceptance procedure beyond the FAQ and admin-dashboard docs.
  • No published performance benchmark for kiwix-serve / the Hotspot: no documented requests-per-second, latency or throughput figure to target when validating a running instance.
  • No formal cold-climate / low-temperature operating test: the Ladakh deployment (long freezing winter, high altitude) is documented as a field use case, but upstream gives no tested minimum operating temperature, condensation handling, or battery/charge behaviour in the cold for the RPi 5 / hotspot.
  • No defined multi-user concurrent-load threshold or test procedure: 'up to 24 devices' is stated as a capability, but there is no documented load test (clients, throughput, failure point) to verify it under sustained load.
  • No documented ZIM-integrity / checksum verification step in the deployment or OS-only guide: the OS-only setup does not describe how to confirm a ZIM is uncorrupted (checksum/sha256) before it is served.
  • Incomplete automated test coverage on the primary client: Android project test coverage is ~57.68% (patch coverage 75% on PR #4426), so the Reader's behaviour on the target low-end hardware is only partially covered by automated tests.
  • No documented procedure for updating/refreshing ZIM content in a disconnected deployment once on site (how a field operator pulls in a newer ZIM without internet, or verifies which version is currently installed, given the library picker hides versions/dates).

Safety

Build is a low-risk, no-solder, 5 VDC content-only node. Safe with the controls below; no licensed/qualified person needed for the standard scope. The two items that must be handled are the optional off-grid Li-ion/solar power (use only certified cells/BMS, protect from sun/heat/shorts) and thermal management in hot climates (keep the Active Cooler in, ventilate the enclosure, keep out of direct sun). N/A: gas-combustion (no gas, no combustion), pressure (no pressurized parts), water-food (no potable-water or food-contact function). Not a medical device: it serves medical knowledge content for reference only and must not be used for clinical diagnosis or patient care.

Evidence

The strongest findings from Applied Commons research on this project:

  • The image-bearing Medical 'bundle' is a 64GB content bundle (MDWiki Medical Encyclopedia, WikEM, MedlinePlus, CDC traveler's health, NHS Medicines A to Z, military/field medicine manuals, video collections), sold as a pre-installed Kiwix Hotspot (Raspberry Pi + SSD + case + charger) or as an OS-only Raspberry Pi image. It is not distributed as a phone-app download; a 64GB image-bearing bundle exceeds the storage of typical USD 50-60 handsets, so on a handset it is storage-bound, not merely CPU/RAM-bound.
  • Kiwix Hotspot hardware: Raspberry Pi 5 + 4GB RAM, 256GB NVMe M.2 SSD (expandable to 1TB); serves up to 24 WiFi clients simultaneously; 4-9W energy consumption; 'powerable off a powerbank or a small solar panel'. Supported content-bundle hardware is Raspberry Pi 3B/3B+/4B/400/5/500; Raspberry Pi Zero 2W is explicitly not supported 'due to its limited memory'. Power-supply spec per bundle page: 12.5W for Pi Zero2W/3B/3B+, 15W for Pi 4/400, 27W for Pi 5.
  • Low-memory search was a real, reported defect (tracking ticket issue #4399) and was fixed on main. PR #4426 'Improved search performance on low-memory devices' (merged 2025-09-22 into main; body says 'Fixes #4399') moved search and result-fetching to the IO thread, cut per-keystroke result fetches from 100 to 20, added a 150 ms debounce, and removed a duplicate search trigger. Both tablet reporters confirmed a pre-built dev APK from the issue thread restored normal performance (Xperia XZ3: 'performance seems to be back to normal', 2025-09-11; Note Air 3: 'much, much better', 2025-09-22) - so the fix is a verified performance/memory reduction, not a marketing claim.
  • Update cadence is per-recipe periodicity enforced by Zimfarm ('it decides when a ZIM file should be recreated, based on the recipe'). Measured from actual build timestamps (last ~10 builds per recipe): Hindi medicine dump median gap ~31d (monthly 2025-03..2025-09, then gap, resumed 2026-05/08); en/fr medicine ~90d (quarterly); de/en/es/fr climatechange ~34-40d (monthly); TED topic sets ~90d (quarterly); canadian-prepper ~90d; usda-2015 static (one build 2025-04-11); zimgit post-disaster only rebuilt on upstream git changes (2021-12..2024-05, now disabled). No weekly/daily rebuilds observed in the pipeline.
  • Current kiwix-android (v3.14.0, Aug 2025) + a current no-pictures English Wikipedia ZIM (wikipedia_en_all_nopic_2025-08) was reported 'unusable' on a 4GB-RAM Boox Note Air 3 tablet (Android 12): 30+ s to open the app, 30-45 s per typed search character, 30-60 s per article; a 2022 app (v3.6.0) + 2018 ZIM on the same device loaded in seconds; the same build ran smoothly on a 12GB Pixel 6 Pro. A second reporter (Sony Xperia XZ3, LineageOS) independently reported the same slow/stale search. Because a 1-2GB handset is strictly below the 4GB test device, the current app is expected to be at or below the 'unusable' baseline on such handsets in any build lacking the fix.
  • Release-status caveat (verified via GitHub compare API, 2026-10-26): the low-memory search fix (PR #4426) is an ancestor of current main, but is NOT backported into the latest stable release v3.14.1 (published 2026-05-14). The merge-base of the fix commit and the v3.14.1 tag is a Feb-2025 commit, and the 13 v3.14.1-only commits are publishing/ObjectBox/dependency maintenance with no search fix. So users on the stable 3.14.x line do not have the fix yet; it is in main/nightly/dev builds only.
  • Kiwix's official FAQ states kiwix-serve 'is multiplatform (Linux, FreeBSD, macOS, Windows) and is very lightweight: it runs on Raspberry Pi Zero and NAS appliances'. The Kiwix wiki Android page states the project targets 'emerging countries' and 'the cheapest devices', with tablets as the primary target and smartphones secondary. These are design-intent statements, not measurements. (The wiki/Android text was re-verified against the live page on 2026-11-01.)
  • Shared-instance reach to the target segment is demonstrated. Kiwix4School Phase 2 (Wikimedia Rapid Fund, USD 3,000 / 8,200,465 TZS, Dec 2024-Jan 2025) installed Kiwix offline resources in Benjamin Mkapa Secondary School and Kajengwa Primary School in Tanzania, with teacher training, community outreach, and ongoing technical support. The report itself names 'the need for more localized Swahili content' and device/education constraints as open challenges - i.e. reach is real but content-localization and device-ownership remain gaps.
