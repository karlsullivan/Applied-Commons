Open-source (GPL-3.0, 962-star kiwix-tools; 20+ years old, 10M+ users in 212+ countries) suite that brings free knowledge (Wikipedia, medical guides, educational videos, repair manuals and custom content) offline via downloadable ZIM files, readable on any low-cost device including a Raspberry Pi or a Wi-Fi hotspot, in 100+ languages. COLD-CLIMATE GROUNDED: the Kiwix site documents a school running entirely on a Kiwix Hotspot in the remote, high-altitude, long-freezing-winter region of Ladakh (India), and users working off-grid ('I work off grid and Kiwix allows me to keep access to my data at all times').

Assembly

Tools: Raspberry Pi Imager (raspberrypi.com/software) - free, microSD card writer with the card (Imager writes directly; no separate dd/burn tool needed), USB-C PSU rated for the Pi model: 12.5W (Pi 3B/3B+), 15W (Pi 4/400), 27W 5V/5A (Pi 5, per Raspberry Pi spec), Any Wi-Fi-enabled client device (smartphone, feature phone with browser, laptop) for verification, Optional: browser + download client for ZIM files (library.kiwix.org) or torrent client for the image download, Optional (large content): Docker host for self-hosting the Imager Service (upstream README: 256GB per writer worker) or $99/month Kiwix Imager server access, Retail path instead of DIY: Kiwix Hotspot unit from get.kiwix.org shop (CHF 260), no additional tools - it is plug-and-play
Skills: Flash an SD card image with a GUI imager (following on-screen prompts; no command line required), Connect a device to an open Wi-Fi hotspot and open a captive portal, Use a web browser over http (not https) on a local hotspot network, Upload/choose ZIM files via a web-based admin panel (ZIM Manager / File Manager), Match the Pi model to its required PSU wattage (basic electronics safety: under-powering causes brownouts), Optional: swap the retail unit's NVMe SSD for a larger one (upstream FAQ: flash an image on it or transfer from the old disk)
Time: DIY: 2-6 hours total for a first build - most of it the image download (image size is listed on the bundle page and can be tens to hundreds of GB); flashing itself is minutes, first boot wait is 5-8 minutes, and initial verification is under 15 minutes. Retail: under 1 minute to reach the Wi-Fi network per the product page (plus ~10 working days shipping via Swiss Post). Adding large content via Imager Service adds build time per image (up to 1TB images since v3.0, 4x faster build than before).

  1. Choose the path and order hardware (bill of materials) DIY: one supported Raspberry Pi - 3B, 3B+, 4B, 400, 5, or 500 (upstream explicitly does NOT support the Pi Zero 2W, 'due to its limited memory') - plus a microSD card with enough space for the image (size listed on the Kiwix bundle page) and the USB-C PSU rated for the model: 27W 5V/5A for Pi 5 per Raspberry Pi's spec (upstream FAQ cites 12.5W for Pi 3B/3B+ and 15W for Pi 4/400; the Pi 3B/3B+ and Pi 4/400 wattage figures come from Kiwix's own FAQ, the 27W/5V-5A figure from raspberrypi.com). Retail alternative: buy the Kiwix Hotspot (CHF 260; CHF 330 with the Preppers Premium content bundle) - Pi 5 4GB, 256GB NVMe M.2 SSD (expandable to 1TB), Argon NEO 5 aluminium case with heatsinks and active fan, CR2032 RTC battery, up to 24 client devices, 4-9W draw, powerable from a powerbank or small solar panel.
    Caution: Buy the correct PSU for the Pi model: an under-rated supply causes brownouts, data corruption on the SD card/SSD and failed boots. Keep the CR2032 coin cell away from metal objects and do not puncture it; it is a lithium cell.
  2. Obtain the Kiwix Hotspot OS image For DIY, download the OS-only image: either a free OS-only image from get.kiwix.org's OS-only setup guide page, or a pre-packaged content bundle (OS-only editions: Wikipedia/Preppers/Computer CHF 15-25, Preppers Premium CHF 40, 64GB-512GB). The image filename looks like demo_yyyy-mm_xxxxxxxx.img or similar. For very large libraries (hundreds of GB to 1TB), upstream recommends building a custom image with the Imager Service - a self-hosted Docker stack (manager, scheduler, creator, downloader, writer workers plus an FTP 'warehouse'; the writer host needs ~256GB per worker) per its README, or paying $99/month for unlimited access to Kiwix's own build servers (per the Hotspot Imager 3.0 release notes).
    Caution: Download over a checked channel (the bundle page lists the image size - verify your download matches it) to avoid writing a corrupt or truncated image to the card.
  3. Flash the image onto the microSD card with Raspberry Pi Imager Launch the Raspberry Pi Imager (raspberrypi.com/software). Do NOT use the 'Choose device' button. Select the downloaded image via 'Choose OS -> Use custom', select the SD card via 'Choose storage', click Next, answer 'No' to OS customisation, and confirm 'Yes' to the warning that the SD card will be erased. Make sure the card has enough free space for the image and let the imager run its full verification step so the write is confirmed correct. Upstream is explicit: do not change any of the settings (network name or whatnot) as it bricks the system.
    Caution: The imager erases everything on the selected card - select the correct storage device. Do not touch 'OS customisation' or any settings; upstream warns this locks/bricks the boot system.
  4. Insert the card and power on the Pi Insert the flashed microSD card into the Raspberry Pi (upstream note: the Pi 5's NVMe path is for the retail unit; the DIY image boots from microSD) and connect the model-rated USB-C PSU. First run: after 1-8 minutes (depending on device and disk) a 'Kiwix Hotspot' network (or the name chosen in the Imager service) appears; the guide also says to allow 5-8 minutes for the first boot to unpack everything before the network shows - subsequent boots are much faster. The Pi 5 has a power button, so use it (or unplug) rather than yanking power, especially on NVMe-based retail units.
    Caution: Do not power off mid-flash or during first-boot unpacking: interrupting the boot preparation can leave the system unbootable and require a re-flash.
  5. Connect a client device to the hotspot On a phone, laptop or any Wi-Fi-capable device, connect to the open 'Kiwix Hotspot' Wi-Fi network (no password on the default image). A captive portal appears; alternatively type the full address goto.kiwix.hotspot (or network-name.hotspot if renamed in the Imager service) in a browser. Upstream emphasises: use http, NOT https - the local certificate is not trusted. The retail unit reaches a connectable network in under a minute (plug in power, done - it ships with the full OS and sample content).
    Caution: None beyond network hygiene: the hotspot is open and local only; clients do not get internet through it, so no external traffic exposure is documented.
  6. Verify a running instance (test) Browse to a ZIM article from a client device (sample content ships with the OS) and confirm pages, images and search work offline - disconnect the client from any other Wi-Fi to prove content is served from the hotspot. For multi-user, connect a second device and load an article simultaneously (the hotspot supports up to 24 devices). Open the admin dashboard at admin.kiwix.hotspot with the default credentials admin / admin-password (link also in the dashboard footer) and confirm the ZIM Manager and File Manager list the installed content. For deeper OS access (Debian base), upstream documents console login user / raspberry with keyboard+screen, or SSH if enabled via the console or admin dashboard.
    Caution: Treat the default credentials (admin/admin-password, user/raspberry) as deployment blockers: if the hotspot is placed in a shared or public setting, change them through the admin dashboard/OS before handover - upstream documents the defaults but does not document a password-change procedure, so treat this as a gap.
  7. Add and manage content (ZIM files) On a running hotspot, use the Admin Panel -> ZIM Manager to add content, or the File Manager to upload your own files (both are in the admin dashboard). ZIM files can be downloaded from library.kiwix.org. Upstream caveat: transferring large files over the hotspot's own Wi-Fi network 'can be frustrating because of its speed', so most people build large hotspots with the Imager Service and flash the resulting image instead. On the retail unit you can also swap the 256GB NVMe for a larger disk (expandable up to 1TB per spec) - upstream: you'll have to flash an image on it or transfer from the previous disk.
    Caution: When swapping the retail NVMe, back up or note the content on the old disk first (upstream documents the swap but not a backup procedure); power the unit off before touching the M.2 slot.
  8. Operate off-grid or from battery (optional deployment mode) The retail hotspot draws 4-9W and upstream states it can be powered from a powerbank or a small solar panel; a rechargeable RTC battery keeps the clock running when unpowered. DIY equivalents follow the Pi model's power draw (12.5W / 15W / 27W per upstream's technical-requirements FAQ) - size any battery/solar supply against that plus headroom. Kiwix documents real off-grid deployments, e.g. a school in the high-altitude, freezing-winter region of Ladakh running on a Kiwix Hotspot.
    Caution: Solar/battery operation: charge batteries in a ventilated, fire-safe location and keep the coin-cell RTC and any Li-ion pack away from the cold-weather exposure that degrades them (Ladakh deployments document the device running there, but upstream does not publish a low-temperature operating range).

Failure modes

FailureEffectMitigation
Kiwix Reader v3.14.0 becomes unusable on a low-end Android tablet with a large modern ZIM (wikipedia_en_all_nopic_2025-08).App takes 30+ seconds to open; each typed search character blocks 30-45s; opening an article takes 30-60s; queries longer than 5 characters return no results. Older ZIM (2018) in the old app (3.6.0) loads in seconds, so the regression is version/ZIM-dependent.Apply the fix from PR #4426 (move search to the IO thread, fetch 20 results instead of 100 per keystroke, add 150ms debounce, keep the UI thread free) and/or use a smaller ZIM variant; confirm search responsiveness returns to a couple of seconds on the target device.
Transferring a large ZIM to an Android device over USB MTP is slow and buggy.MTP caps at ~37 MiB/s (about 30% of connection speed) and is unreliable for big files - an 115GB ZIM can take ~an hour and may corrupt in transfer.Use USB-debugging 'adb push' (reported ~33 MB/s, copied successfully) or a Wi-Fi file-explorer transfer (up to ~80 MiB/s in practice) instead of MTP; verify the received file size/checksum before importing.
ZIM-version / app-version mismatch (an old app cannot open a newer ZIM).Kiwix 3.6.0 cannot open the current ZIM format, and the old ZIM in the new app is still slow - the pairing of app and ZIM determines whether the deployment is usable.Pair a current Reader build with a current (or format-compatible) ZIM, and re-run the search/performance acceptance check on the actual deployment hardware after pairing; pin the known-good app+ZIM combination in the deployment notes.
The Play Store Kiwix APK is restricted to a couple of directories for ZIM storage.Users who put the ZIM elsewhere (a common field practice) cannot find it; the library picker does not show versions or dates, so the wrong/old ZIM can be loaded.Store the ZIM under the allowed path (e.g. /Android/media/org.kiwix.kiwixmobile/) or sideload the APK, which can read ZIMs from anywhere; check ZIM version/date in the direct download directory (lb.download.kiwix.org) rather than trusting the library picker.
Slow displays (e-ink) and very low-end devices degrade readability of the Reader.Feature requests flag e-ink support (and, by extension, animation-heavy UI on slow screens) as a usability gap for the cheapest target devices.On e-ink or slow devices, use the disable-animations setting (PR #5090) and a smaller/short-text ZIM; verify content is legible on the actual display type before field release.

Known gaps

What the original design does not document:

  • Kiwix does not document the exact NVMe SSD capacity or part number shipped in the retail Hotspot (only that it is NVMe and ~40x faster than microSD).
  • No upstream bill-of-materials / parts-list file exists for the Hotspot hardware — the retail unit is assembled in-house by Kiwix and no BOM is published in the open repos (libkiwix, kiwix-tools, offspot/base-image, offspot/kiwix-hotspot).
  • The 27W (5V/5A) power figure is from the Raspberry Pi 5 datasheet/spec, not from a Kiwix document; Kiwix does not publish a measured idle or 24-client power draw for the node.
  • No solar/battery sizing document from Kiwix for off-grid operation: the retail unit ships with a rechargeable RTC battery and a standard charger, but Kiwix does not sell a solar kit or publish watt-hours needed for all-day field operation.
  • Price/currency drift: live shop lists CHF 260/330; the 2025 launch blog states USD 319 (tax+shipping). No fixed USD conversion is published, so the USD total is approximate.
  • Feature phones are not directly supported (content is browser-based on a Wi-Fi hotspot); the input's need for feature-phone / SMS / voice access is only partially met.
  • Safety (last-mile multi-hazard early warning) and local-language agricultural-advisory content are not present in the standard retail content bundles; the 1,309-ZIM library covers 100+ languages but these specific last-mile topics are a documented gap for this need.
  • Assembly/test steps are implied (flash image, add ZIMs via ZIM Manager/Imager, verify in the browser at the hotspot) but Kiwix does not publish a step-by-step BOM-style assembly+acceptance procedure beyond the FAQ and admin-dashboard docs.
  • No component-level bill of materials with individual part prices: the Kiwix Hotspot page sells the assembled unit (standalone CHF 260, Preppers Premium CHF 330; other bundles CHF 260) but does not price the Raspberry Pi 5 4 GB, 256 GB NVMe M.2 SSD, M.2 HAT/adapter, 27 W USB-C power supply, Argon NEO 5 case or CR2032 coin cell separately; the Raspberry Pi 5 product page lists only the 16 GB variant at USD 305, with no 4 GB price.
  • offspot/base-image targets Raspberry Pi 3 models and newer (3A+, 3B, 3B+, 4B, 400, Zero 2 W) per its README, yet the retail Kiwix Hotspot is built on a Raspberry Pi 5 + NVMe SSD; the base-image repo contains a Pi 5 NVMe boot patch (config.txt.patch) but the Pi 5 build/assembly path is not fully documented there.
  • The M.2 HAT/adapter model used to attach the NVMe drive to the Pi 5 is not specified in any retrieved source (the case, Argon NEO 5, is named but not the HAT).
  • No official power-draw figure is published: the documented requirement is a 27 W (5 A) USB-C power supply for the Pi 5 (12.5 W for Pi 3B/3B+, 15 W for Pi 4/400), but the unit's actual operating wattage is not stated upstream; a third-party estimate (~5-8 W, entropysurvival.com) is not official. The RTC battery is a non-rechargeable CR2032 3V coin cell (not a rechargeable battery).
  • ZIM content files are served from a bot-gated library (library.kiwix.org returned an access-confirmation wall) and from date-rotating image URLs (api.imager.kiwix.org 302-redirects to a dated scw.dl.hotspot.kiwix.org build, e.g. demo_2026-10_6abfa2a03f.img), so stable content download links could not be pinned.
  • offspot/kiwix-hotspot (the SD-card hotspot image builder) is marked End-of-Life and superseded by a new generation of tools (offspot/overview); its code base no longer receives fixes, so the current generation's tooling is only partially indexed here.
  • No documented procedure to change the default admin (admin/admin-password) or console (user/raspberry) credentials; the defaults are published but a lock-out or password-reset procedure is not.
  • No documented failure-recovery path if the image write/verification fails or the first boot does not produce the hotspot network (no re-flash/repair guide beyond 'flash it again' implied by the imager instructions).
  • No documented backup/update/OTA procedure for the running hotspot OS or for its ZIM content (content updates are framed as new images via Imager Service, but the upgrade process on an installed unit is not step-by-step).
  • No documented procedure for adding content to the retail unit beyond ZIM Manager / File Manager uploads (and the NVMe swap FAQ) - e.g. no scheduled content refresh workflow.
  • No published low-temperature or dust/rating spec for the retail aluminium case, despite documented cold-climate (Ladakh) and off-grid use; sizing a solar/battery supply for DIY units is left to the builder using only the 12.5W/15W/27W draw figures.
  • Supported-model list excludes Pi Zero 2W ('plan to support'), and no other failure modes (corrupt card, bricked-by-customisation recovery) are documented - a bricked-by-customisation card appears to require re-flashing, which is not spelled out.
  • No published performance benchmark for kiwix-serve / the Hotspot: no documented requests-per-second, latency or throughput figure to target when validating a running instance.
  • No formal cold-climate / low-temperature operating test: the Ladakh deployment (long freezing winter, high altitude) is documented as a field use case, but upstream gives no tested minimum operating temperature, condensation handling, or battery/charge behaviour in the cold for the RPi 5 / hotspot.
  • No defined multi-user concurrent-load threshold or test procedure: 'up to 24 devices' is stated as a capability, but there is no documented load test (clients, throughput, failure point) to verify it under sustained load.
  • No documented ZIM-integrity / checksum verification step in the deployment or OS-only guide: the OS-only setup does not describe how to confirm a ZIM is uncorrupted (checksum/sha256) before it is served.
  • Incomplete automated test coverage on the primary client: Android project test coverage is ~57.68% (patch coverage 75% on PR #4426), so the Reader's behaviour on the target low-end hardware is only partially covered by automated tests.
  • No documented procedure for updating/refreshing ZIM content in a disconnected deployment once on site (how a field operator pulls in a newer ZIM without internet, or verifies which version is currently installed, given the library picker hides versions/dates).

Safety

Low-voltage, plug-and-play offline-content appliance; safe to build and deploy once the listed controls are applied. No licensed/qualified-person step is required (no mains wiring, gas, pressure, load-bearing structure, or regulated medical-device use). Build pack already covers PSU selection and thermal protection; it does not yet cover RF/certification, credential+Wi-Fi-passphrase change, Li-ion charge discipline for off-grid use, or a medical-reference disclaimer — add those.

HazardSeverityControls
Under-rated or wrong USB-C PD power supply on the Pi 5: the node needs the 27W (5V/5A) supply; a lower-rated supply or a sub-spec / data-only USB-C cable causes brownouts, microSD/NVMe write corruption, failed first boots, and can damage the board. (Low-voltage 5V USB-C only — no mains, no earthing/earthing-fault path, no high current to a user.)lowUse the model-rated USB-C PD supply — 27W 5V/5A for the Pi 5, 15W for Pi 4/400, 12.5W for Pi 3B/3B+ (Raspberry Pi spec; Kiwix FAQ) — do not substitute a lower-rated charger.; Use a 5A USB-C PD cable (not a data-only or 3A phone cable) so the cable itself does not drop voltage under load.; Verify the Pi boots and stays stable under multi-client load before deployment (a brownout shows as reboots / storage corruption).
Batteries: (a) the CR2032 coin cell used for RTC clock retention is a lithium button cell — puncturing, crushing, shorting the terminals, or heating it can make it vent/leak and ignite; (b) for the optional off-grid mode the unit is powered from a rechargeable Li-ion powerbank or solar+battery pack — a damaged, swollen, overcharged, or frozen-then-charged Li-ion pack can thermally run and ignite. Build pack already notes coin-cell handling and 'charge in a ventilated, fire-safe location', but does NOT give Li-ion charge/transport controls.mediumKeep the CR2032 away from metal objects / conductive surfaces; never puncture, crush, heat, or short the terminals; replace only with a CR2032 3V.; Charge Li-ion powerbanks/battery packs in a ventilated, non-flammable location; use the manufacturer's charger (or a proper charge controller for solar); never charge a damaged, swollen, or hot pack.; Cold-climate (Ladakh) use: keep the pack warm when charging, expect reduced capacity in the cold, and do not charge a frozen pack.
Sustained full load (up to 24 clients, large-ZIM reads) raises board temperature; the Pi 5 relies on heatsinks plus an active fan. In arid/dusty environments dust builds up in the fan/vents, reducing cooling and causing thermal throttling or long-term degradation; the hot aluminium case is a mild contact-heat risk if gripped by a child.lowProvide ventilation; do not seal the unit in a dust-tight box that blocks the fan (if a sealed enclosure is required, use passive cooling only).; Periodically clean dust from the fan/vents (especially arid deployments); confirm the fan runs under load (already an acceptance step).; Mount so the hot aluminium case is not where a child can grip it for long.
The Hotspot is a Wi-Fi access point in the 2.4 GHz (and 5 GHz) ISM bands. Transmit power and band use must stay within the certified limits of the Pi's Wi-Fi module for the country of deployment; modifying the antenna, adding a repeater/amplifier, or re-flashing with an uncertified radio image can push emissions out of spec and cause interference — an uncertified/modified transmitter is a regulatory breach in most jurisdictions. A standard consumer AP needs no operator licence.lowUse the unmodified Kiwix Hotspot OS, stock Wi-Fi module, and stock antenna; do not attach a higher-gain antenna, add a repeater/amp, or re-flash with an uncertified radio image.; Keep emissions within the module's certified transmit power (no external amplification).; For multi-hotspot deployments, space units or set non-overlapping channels to avoid mutual interference.
Cyber/operational: on the default image the 'Kiwix Hotspot' SSID is OPEN (no Wi-Fi password) and the admin dashboard (admin.kiwix.hotspot) is plain HTTP (no TLS) with published default credentials (admin/admin-password; console user/raspberry). In a home, school, or village setting anyone nearby can connect, log into the admin panel, change or erase content, or disable the device — and because the unit is content-only and read-only, tampering is not something it alerts on.mediumChange the admin (admin/admin-password) and console (user/raspberry) credentials to strong, unique values before handover (the pack already flags the defaults as a deployment blocker).; Set a WPA2/WPA3 passphrase on the hotspot so only intended users connect (the default open SSID is a risk in shared settings).; Disable SSH and lock the admin dashboard to trusted local devices if not needed; treat the plain-HTTP dashboard as reachable only from the local hotspot network.
The device serves offline MEDICAL reference content (Medical bundle; Preppers Premium adds medical; the 1,309-ZIM library includes medical guides). It is a reference source, not a diagnosis/treatment tool, stores no patient data, and is not a regulated medical device (so IEC 60601 does not apply to the hardware). The risk is a lay user in a low-resource setting acting on the content as if it were clinical care, or relying on it when urgent care is needed.lowLabel the deployment 'offline reference only — not a substitute for professional medical care; seek urgent care for emergencies'.; Prefer curated, vetted medical ZIMs (WHO/UNICEF/peer-reviewed) for clinical-adjacent topics rather than unvetted sources.; Confirm the unit is content-only and read-only with no write-back/forms (the pack's read-only + ZIM-integrity confirmation already covers the 'no patient data' point).

Evidence

The strongest findings from Applied Commons research on this project:

  • The image-bearing Medical 'bundle' is a 64GB content bundle (MDWiki Medical Encyclopedia, WikEM, MedlinePlus, CDC traveler's health, NHS Medicines A to Z, military/field medicine manuals, video collections), sold as a pre-installed Kiwix Hotspot (Raspberry Pi + SSD + case + charger) or as an OS-only Raspberry Pi image. It is not distributed as a phone-app download; a 64GB image-bearing bundle exceeds the storage of typical USD 50-60 handsets, so on a handset it is storage-bound, not merely CPU/RAM-bound.
  • Kiwix Hotspot hardware: Raspberry Pi 5 + 4GB RAM, 256GB NVMe M.2 SSD (expandable to 1TB); serves up to 24 WiFi clients simultaneously; 4-9W energy consumption; 'powerable off a powerbank or a small solar panel'. Supported content-bundle hardware is Raspberry Pi 3B/3B+/4B/400/5/500; Raspberry Pi Zero 2W is explicitly not supported 'due to its limited memory'. Power-supply spec per bundle page: 12.5W for Pi Zero2W/3B/3B+, 15W for Pi 4/400, 27W for Pi 5.
  • Low-memory search was a real, reported defect (tracking ticket issue #4399) and was fixed on main. PR #4426 'Improved search performance on low-memory devices' (merged 2025-09-22 into main; body says 'Fixes #4399') moved search and result-fetching to the IO thread, cut per-keystroke result fetches from 100 to 20, added a 150 ms debounce, and removed a duplicate search trigger. Both tablet reporters confirmed a pre-built dev APK from the issue thread restored normal performance (Xperia XZ3: 'performance seems to be back to normal', 2025-09-11; Note Air 3: 'much, much better', 2025-09-22) - so the fix is a verified performance/memory reduction, not a marketing claim.
  • Update cadence is per-recipe periodicity enforced by Zimfarm ('it decides when a ZIM file should be recreated, based on the recipe'). Measured from actual build timestamps (last ~10 builds per recipe): Hindi medicine dump median gap ~31d (monthly 2025-03..2025-09, then gap, resumed 2026-05/08); en/fr medicine ~90d (quarterly); de/en/es/fr climatechange ~34-40d (monthly); TED topic sets ~90d (quarterly); canadian-prepper ~90d; usda-2015 static (one build 2025-04-11); zimgit post-disaster only rebuilt on upstream git changes (2021-12..2024-05, now disabled). No weekly/daily rebuilds observed in the pipeline.
  • Current kiwix-android (v3.14.0, Aug 2025) + a current no-pictures English Wikipedia ZIM (wikipedia_en_all_nopic_2025-08) was reported 'unusable' on a 4GB-RAM Boox Note Air 3 tablet (Android 12): 30+ s to open the app, 30-45 s per typed search character, 30-60 s per article; a 2022 app (v3.6.0) + 2018 ZIM on the same device loaded in seconds; the same build ran smoothly on a 12GB Pixel 6 Pro. A second reporter (Sony Xperia XZ3, LineageOS) independently reported the same slow/stale search. Because a 1-2GB handset is strictly below the 4GB test device, the current app is expected to be at or below the 'unusable' baseline on such handsets in any build lacking the fix.
  • Release-status caveat (verified via GitHub compare API, 2026-10-26): the low-memory search fix (PR #4426) is an ancestor of current main, but is NOT backported into the latest stable release v3.14.1 (published 2026-05-14). The merge-base of the fix commit and the v3.14.1 tag is a Feb-2025 commit, and the 13 v3.14.1-only commits are publishing/ObjectBox/dependency maintenance with no search fix. So users on the stable 3.14.x line do not have the fix yet; it is in main/nightly/dev builds only.
  • Kiwix's official FAQ states kiwix-serve 'is multiplatform (Linux, FreeBSD, macOS, Windows) and is very lightweight: it runs on Raspberry Pi Zero and NAS appliances'. The Kiwix wiki Android page states the project targets 'emerging countries' and 'the cheapest devices', with tablets as the primary target and smartphones secondary. These are design-intent statements, not measurements. (The wiki/Android text was re-verified against the live page on 2026-11-01.)
  • Shared-instance reach to the target segment is demonstrated. Kiwix4School Phase 2 (Wikimedia Rapid Fund, USD 3,000 / 8,200,465 TZS, Dec 2024-Jan 2025) installed Kiwix offline resources in Benjamin Mkapa Secondary School and Kajengwa Primary School in Tanzania, with teacher training, community outreach, and ongoing technical support. The report itself names 'the need for more localized Swahili content' and device/education constraints as open challenges - i.e. reach is real but content-localization and device-ownership remain gaps.
