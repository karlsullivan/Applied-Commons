Free, open-source (GPL) hardware and software platform for autonomous UAVs (flight controller, autopilot, ground station); low-cost, self-buildable and field-replaceable. Used by hobbyists, universities and companies on vehicles from 11.9 g to 25 kg. Cold-climate proof: the open-source fixed-wing Paparazzi UAV carried the survey camera for the Kanderfirn alpine glacier monitoring (high mountain, low air pressure, poor GPS), demonstrating open, low-cost aerial mapping hardware that operates in cold, harsh environments.

Assembly

Tools: Fine temperature-controlled soldering iron, Hot-air rework station (required for BGA IMU and QFN64 MCU), Solder paste stencil cut from the Apogee v100 Paste Mask gerber, Magnifying lamp / microscope for SMD inspection, USB mini-B cable (DFU firmware download and SD mass-storage access), SWD JTAG probe (cheap STM32 Discovery board ~$8, or CricketProbe / Black Magic Probe) for SWD path, Linux workstation (Ubuntu) with dfu-util, make, gcc-arm, python, GCS computer running Paparazzi Center, Multimeter for post-build rail and continuity checks
Skills: Fine-pitch SMD hand-soldering and hot-air reflow, Basic electronics safety (ESD, capacitors, lithium battery charging if used), Git / Makefile workflow on Linux, ARM firmware flashing via DFU and SWD, Paparazzi airframe XML configuration (board target, modules, telemetry), Sensor calibration (accelerometer, magnetometer, barometer, airspeed), UAS pre-flight checks (VLOS, failsafe, geofence)
Time: Buy pre-built Apogee v1.0: ~2-4 h end-to-end (firmware build + flash + calibration + pre-flight). Build from scratch (BOM sourcing, 4-layer PCB, SMD assembly, firmware, calibration, pre-flight): ~8-16 h for an experienced SMD builder on first pass; ~4-8 h for a second, more practiced pass. These figures are build-pack estimates, not sourced measurements.

  1. Choose build path: buy pre-built Apogee v1.00, or build from scratch (BOM + 4-layer PCB + SMD assembly) The Apogee v1.00 wiki lists Drotek, EasyDrone, GoodluckBuy, Alibaba and TaoBao as retail sources for pre-assembled boards; the Get Hardware wiki page adds 1BitSquared and Luftfotos24, and lists PCB fabs (PPZUAV, Seeed Fusion, OSH Park, PCBShopper). Building from scratch: source the 4-layer PCB (the hardware repo's fab notes name eurocircuits as the intended fab) and order every item in the official Apogee_v100_BOM.xls (Digi-Key part numbers included for the passives, Molex Picoblade headers, MicroSD socket, etc.).
    Caution: Buy from a retailer that ships the board as a matched revision (v1.00, July 2013); a mixed BOM with the current software release may need a revision check before first power.
  2. Assemble the SMD board from the 4-layer PCB + full BOM (reflow path) Print the top/bottom component layout images from the wiki. Stencil the paste mask, apply solder paste, place all SMD passives, the Molex Picoblade headers (RC, SWD, UART1/4/6, I2C1/2, SPI1, AUX, SRV0-5, USB/RC), the MicroSD socket, the four status LEDs, the TPS62112 buck, the LM3940 and TPS73633 LDOs, the TPS2051B aux switch, and the two 16 MHz / 32.768 kHz crystals. Re-flow the fine pitch parts: the BGA IMU (MPU-9150 or MPU-6050) and the STM32F405 QFN64 need a hot-air method per the hardware repo's fab notes — a fine temperature-controlled iron is used for the rest.
    Caution: Observe ESD precautions for the IMU and MCU; verify tantalum capacitor polarity before applying any power (a reversed 33uF or 100uF cap can short the 3.3V rail); confirm no solder bridges between the GND and +3.3V internal planes with a multimeter before powering.
  3. First power-on and inspection Plug the USB mini-B cable before power: the board enters DFU mode (per the wiki's USB Modes section) and the four status LEDs should light. Verify the 3.3V and 5V rails at the test points with a multimeter, and confirm the MCU enumerates on the host as a DFU device.
    Caution: Do not apply power with a short present; a hot board or smoke means a rail short — unplug immediately and re-inspect.
  4. Build and flash the Paparazzi firmware (DFU path) Clone the Paparazzi source (the Apogee source code is in the git master branch, per the wiki's Source code section), install the build dependencies, configure an airframe file with <target name="ap" board="apogee_1.0"> (or apogee_1.0_chibios for on-board SD logging), build the 'ap' target, then flash with dfu-util over USB-DFU using a usb-mini cable. The wiki's Programming section notes the MCU's native DFU bootloader is embedded in ROM, so no pre-loaded external bootloader is needed. For the alternate SWD path, the wiki names st_flash and st_util (compile from source) plus a molex-to-2.54mm pin cable and a cheap stm32 discovery board (~$8).
    Caution: Verify the dfu-util output before releasing the board; a failed flash can leave the MCU in an unresponsive state requiring SWD recovery.
  5. Set up the ground station and airframe Run Paparazzi Center on the GCS, select the airframe, and open the Flight UDP/Wifi or serial session. The tutorials index on the devel docs lists GCS Setup and Airframe Setup as the expected next pages (content not retrieved; see gap 5).
    Caution: Confirm telemetry lock before arming; an unbound GCS will not receive failsafe commands.
  6. Sensor calibration (accelerometer, magnetometer, barometer, airspeed) The tutorials index lists a dedicated Sensor Calibration page (content not retrieved; see gap 5). The stable docs recommend calibrating the drone before flying; the Bebop-2 first-flight page (retrieved) shows the same calibration-then-fly pattern and joystick-connection guidance that applies to the fixed-wing Apogee build.
    Caution: Calibrate the accelerometer on a flat, vibration-free surface; a mis-leveled calibration produces a persistent heading drift.
  7. Pre-flight and first flight VLOS check, failsafe (RC loss, telemetry loss) arming, and a geofence review before the first flight. The tutorials index lists Testing and Tuning as the follow-on page (content not retrieved; see gap 5). The input's fit notes confirm the platform operates at ~0.8 km2/flight at 5-7.7 cm/px GSD with 500 m VLOS telemetry.
    Caution: Fly within VLOS at 500 m; keep manual RC backup available; respect local UAS regulations.

Known gaps

What the original design does not document:

  • GCS (ground-control-station) computer is NOT costed: the paper states the ~1300 EUR covers the UAS incl. camera and remote control but explicitly WITHOUT the GCS computer.
  • No per-part prices are published for the Apogee v1.00 board components (the project's own BOM lists part numbers/descriptions but no unit cost); board-level costs are left null rather than guessed.
  • Total is not a fixed figure: Table A1 states costs are 'only rough estimates'; component sum is EUR 1270 while the paper rounds to 'about 1300 EUR'.
  • No supplier/store link is given for the 'Navilock' GPS or the SLS battery in Table A1 (only manufacturer names).
  • The full UAS BOM (Table A1) is documented in the Kanderfirn journal article, not in the Paparazzi project's own repo/wiki; the Paparazzi wiki documents the Apogee board BOM but not the complete aircraft.
  • Consumables (LiPo charger, RC battery, spare propellers, Teflon GCP markers, SD cards) are not itemised in any retrieved source.
  • No 3D CAD (STEP/IGES/FreeCAD) for most boards; only a handful of boards have enclosure CAD (Bebop2 damper STL/SCAD, LiA breakout box STL, STM32F4DISCO daughterboard DXF). The overwhelming majority of hardware is Eagle v4/v5 .sch/.brd with no exchangeable 3D model.
  • No modern KiCad project files for the core flight controllers; the hardware repo is frozen (last commit 2017-06-27) and uses legacy Eagle v4.11 binary formats that newer tools read only with difficulty.
  • No IPC-2581 or ODBC/ODB++ manufacturing packages; fabrication is covered only by per-board gerber/drill exports (fab/ and gerber/ dirs) for some boards, not all.
  • No consolidated per-board BOM for most boards; BOMs exist only for a few (Booz, LiA breakout, STM32F4DISCO daughterboard, Viking EVCU), and several are in legacy .ods format.
  • No documented parts sourcing / supplier mapping (DigiKey/Mouser part numbers) for the core LISA-M / Apogee / PX4Fmu flight controllers; the build relies on the board makefile, not a BOM.
  • The main repo does not pin submodule commit SHAs in-tree (they are in .gitmodules as URLs, not revs), so a fresh clone of the default branch head may pull a newer ChibiOS/pprzlink/fatfs than was tested; exact submodule revs are not recorded in a single file.
  • No bill of materials or cost estimate for the whole airframe (fuselage, actuators, ESC, GPS, telemetry radio, camera) — the hardware repo covers only the flight-controller / sensor PCBs, not the full vehicle.
  • No documentation of a complete assembled example airframe with mechanical drawing (fuse, motor mount, camera gimbal); assembly detail lives in prose docs, not a mechanical CAD package.
  • Seven of the 15 repos (luftboot, PprzGCS, PPRZonDroid, fatfs, ppm-encoder, wiki_import, paparazzi.github.com) state no machine-readable licence; fatfs is FatFs (Chiang) which is LGPL-compatible but no licence file is present in the mirror.
  • No per-file checksums or release artifacts (tagged tarballs) are indexed here; files are pinned to the default-branch head commit only.
  • The wiki's own Assembly section for Apogee v1.00 ships only a BOM spreadsheet and four component-layout images — there is no ordered soldering / assembly procedure upstream. The ordered procedure above is reconstructed from the board spec, the BOM, and the hardware repo's fab notes (hot air for the BGA IMU and QFN MCU).
  • No reflow profile, stencil design, or paste-application method is documented in the upstream hardware repo — only the note that a hot-air method is required for the IMU board's BGA gyros.
  • No post-build power-on checklist with expected LED states or rail voltages is published upstream.
  • The 2013 BOM (Apogee_v100_BOM.xls, v1.00 released 07/2013) predates the current software release (the docs homepage I retrieved shows v7.1_unstable); no statement is published aligning the two.
  • The stable docs' first-flight page is Bebop-2 specific; the fixed-wing Apogee airframe-integration, calibration, and joystick pages are only listed in the tutorials index (content not retrieved in this run).
  • No builder reports with per-step timing or gotchas for this board were retrievable in this run; time figures above are build-pack estimates, not sourced measurements.
  • No standardized acceptance-test procedure for a mapping mission exists in the upstream docs (the tutorial site's index is literally 'TBD'); accuracy targets come from ODM documentation and field papers, not from Paparazzi itself
  • No published end-to-end test of the need brief's full chain: Paparazzi -> ortho -> vector extraction / OSM tracing. Upstream stops at raster (orthophoto/DSM), so village/building basemap acceptance cannot be verified against an upstream-documented target
  • No upstream documentation of WASH point-data capture (annotation workflow, schema, local-language labels) on drone imagery; the WASH-side need is documented separately (Oxfam) but no drone-imagery-to-WASH-point pipeline ships with the project
  • No documented field deployment mode for the 'phone-first, no specialist GIS staff' requirement: the platform assumes a GCS computer and a trained operator; no offline phone-based ground-station build is documented
  • Output licensing of processed products (ODbL or otherwise) is not stated in any retrieved ODM/Paparazzi page; the ODbL compatibility assumption in the need brief is unverified
  • Cost documentation is fragmented: the Kanderfirn paper gives a full UAS cost (~1,300 EUR excluding GCS computer) and Mesquita et al. report $995 for their DIY build, but upstream has no bill-of-materials price list; component prices come only from the retailer list
  • ODM hardware guidance is scattered: the install doc recommends 16 GB RAM / 100 GB disk for a few hundred images (RAM table up to 256 GB at 5,000 images) while forum reports add RAM-as-bottleneck and throughput data; there is no single authoritative sizing table
  • Legal test criteria are US-centric in the retrieved sources (FAA Part 107); the target deployment's local UAS regulations (e.g., Africa/Asia jurisdictions) are not covered by the retrieved sources

Safety

Build steps are safe with controls (LiPo fire, mains electrical, solder/foam chemical, heat, prop cutting). The operational phase is the controlling hazard: an autonomous ~1.3 kg fixed wing flown over village buildings/residential areas is a falling-mass-over-uninvolved-persons risk and is not lawful under the EU open category (A3 mandates 150 m from residential and a privately built UAS cannot hold a C-class RID label; A2 needs a C2-class + remote-ID + geo-awareness system the self-build cannot provide) or under US Part 107 without a remote pilot certificate and an over-human/over-populated-area waiver. A qualified/licensed remote pilot and, where applicable, a Specific-category authorization or waiver are required before any populated-area flight. Gas, pressure, water-food, and biological-medical hazards are not applicable to this all-electric platform.

HazardSeverityControls
Autonomous ~1.3 kg fixed wing flown at 100-140 m AGL over villages/buildings: loss of control or autopilot/telemetry failure means a falling 1.3 kg mass over uninvolved persons (people, livestock, structures). The pack's own acceptance criteria target 'building-level' overflight of populated areas, which is the highest-risk part of the mission.highDo not fly over uninvolved persons or populated areas without a qualified remote pilot holding the applicable credential (US Part 107 remote pilot certificate; EU subcategory competency) AND a specific operational authorization / waiver covering over-populated-area flight; Plan and obtain the regulatory authorization for the actual flight area before first populated-area flight (EU Specific category declaration/authorization, or FAA 107.200 waiver); the open category as written does NOT permit the village-overflight mission; Keep a working manual RC backup armed for the whole mission (already in the pack) so a telemetry/autopilot loss triggers immediate manual recovery, not a crash into people; Conduct an airspace/clearance check (no-fly zones, altitude limits, visual line of sight) before each mission; respect the 120 m EU / 400 ft AGL US altitude ceilings, which already cap the 100-140 m survey altitude in most cases
LiPo thermal runaway: the 3S1P 11.1 V 5000 mAh pack is the classic drone fire source. Charging at mains in a home/farm next to the highly flammable EPP foam airframe (and other organics) means a cell short/overcharge/swelling event can ignite the whole workspace, not just the battery.highCharge only on a non-flammable, fire-safe surface (e.g. LiPo-safe bag or ceramic/metal plate) AWAY from the EPP airframe and any combustibles; Never charge unattended or overnight; do not charge a swollen/damaged/cut cell; Use a certified charger set to exactly 3S (11.1 V) cell count with balanced termination; verify cell count against the pack label before every charge; Inspect the pack for swelling, puncture, heat, or electrolyte leak before every flight; retire swollen cells to a safe isolated location (sand/water-rated bucket); Follow the pack's >40% reserve-at-landing discipline to avoid deep-discharge, which degrades and can damage cells
Mains electrical and high-current DC: the 60 A ESC, 42 A 600 W motor, and the 3S LiPo charge bench plus a reflow oven all tie into mains. A home builder wiring the charge station or reflow oven directly, or using an undersized/uncertified charger or extension lead, is an electrocution and wiring-fire risk. High-current DC motor/ESC wiring (tens of amps) can melt and arc if undersized.mediumUse a certified (UL/CE) 3S LiPo charger; do not hand-wire a mains charger; Power the charge bench and reflow oven from a dedicated, correctly rated circuit; use certified extension leads of adequate rating for the load; Verify motor/ESC wiring gauge and connectors are rated for the ~40-60 A draw and are fully insulated; check for melted/loose joints before each flight (the pack's preflight already inspects propellers and control surfaces - extend it to the high-current leads); If any mains wiring is done in the field, it should be by/under the direction of a qualified electrician, not improvised
Rotating/falling cutting hazard: the 12x6 in folding carbon-fiber prop on a 600 W pusher at up to 1250 Kv is a sharp, high-kinetic-energy cutting hazard during install, spin-up, and ground handling; a running prop can sever fingers. The 1.3 kg wing itself is a falling-mass hazard if it drops during assembly (e.g. off a workbench).mediumNever start the motor or touch the prop while it is or can be spinning; remove/secure the prop before moving the airframe; Keep hands, face, and loose clothing clear of the prop plane; wear eye protection when spin-testing on the ground; Verify each control surface's full range of motion and prop clearance (pack already requires this preflight) and carry the spares (servos/prop) it lists, since the airframe is ~1,300 EUR and field replacement is affordable
2.4 GHz radio licensing/exposure: the Graupner 2.4 GHz RC and the XBee 2.4 GHz telemetry both operate in the 2400-2483.5 MHz ISM band. Exposure at these low power levels is far below limits, so RF safety is minimal; the real issue is (a) that a few jurisdictions (e.g. Germany, Japan) still require a radio license or an approved module for 2.4 GHz aircraft control links, and (b) that running two 2.4 GHz links (control + telemetry) on the same band is a reliability/interference risk, not a licensing one.lowUse certified / type-approved radio modules and verify the specific control-link module is license-exempt in the country of operation before first flight; Plan channel separation between the RC control link and the telemetry link to reduce same-band interference, and treat telemetry loss as a normal field event with the manual RC backup (already in the pack)
Build-phase chemicals: soldering-flux fumes from reflow/hand-solder of the 4-layer Apogee SMD board; EPP foam dust from cutting the fuselage; and LiPo electrolyte (flammable organic carbonates, mildly toxic) if a cell is cut or ruptures.lowSolder in a ventilated area (fan/fume extractor) to avoid inhaling flux fumes; Wear a dust mask when cutting EPP foam; Handle LiPo electrolyte with gloves and avoid inhalation/skin contact; treat any electrolyte spill as a flammable-liquid event
Build-phase heat: the reflow soldering oven and soldering iron reach high temperatures; the 60 A ESC and 600 W motor run hot and remain hot after a flight, so hot-plate/hot-component contact can burn hands and ignite nearby organics.lowPlace the reflow oven and soldered boards on a heat-resistant surface, away from the EPP airframe and other flammables; Allow the ESC/motor to cool before handling after a flight; use heat-resistant gloves where appropriate
Airframe structural integrity in flight: a crack or joint failure of the EPP wing in flight leads to an uncontrolled drop. This is a flight-phase structural risk, not a builder collapse/lifting/falls risk (the airframe is light). Notably the EPP foam is a positive: the pack records it is field-repairable (minor tears 'could be easily repaired').lowPre-flight mechanical inspection of joints, control surfaces, and pusher mount (pack already includes preflight and servo inspection); Keep patch/repair material in the field kit (pack already notes EPP is field-repairable) to fix minor damage before re-fly

Evidence

The strongest findings from Applied Commons research on this project:

  • The 0.7-1.2 m XY / 0.7-2.1 m Z accuracy band is a measured ODM 0.4.1 RMSE from exactly the Paparazzi -> ODM pipeline (Kanderfirn case study, Groos et al. 2019): fixed-wing Paparazzi UAV with GoPro Hero 5, 135 +/- 20 m a.g.l. flight altitude, GSD 5.7-7.7 cm/pixel, georeferenced with dGNSS GCPs of <0.1 m accuracy. XY RMSE scaled with orthophoto size (0.7 m for smaller, 1.2 m for larger maps) and Z RMSE spanned 0.7-2.1 m. On identical imagery Pix4D achieved XY RMSE 0.3-0.5 m and Z RMSE 0.4-0.5 m; the authors attribute part of the ODM gap to its georeferencing being an affine transform (translation, scaling, reflection, rotation) that cannot correct radial 'doming'/'fishbowling' lens distortion.
  • RTK/dGNSS (u-blox ZED-F9P) is the most expensive and fully import-dependent line: bare module $127.42 (DigiKey), EVK-F9P-01 eval board $259.03, and a 3DR-sold ZED-F9P Advanced RTK kit with WiFi and compass $540.00; centimetre accuracy additionally requires a separate ground base station.
  • A documented low-cost fixed-wing UAV (2 m EPP foam airframe, STM32-class autopilot, GNSS, 915 MHz telemetry, 4 S LiPo, camera) has a total material cost of US$995 (November 2019 internet prices); the same paper's comparison table reports ~US$1,440 for comparable DIY builds and ~US$15,797 for commercial equivalents.
  • The Paparazzi native board Apogee (STM32F405RGT6 Cortex-M4 168 MHz, MPU-9150 9-DOF IMU, MPL3115A2 barometer, 3x UART, 6x PWM) is sold only by import vendors - Drotek (FR), 1BitSquared (US), Transition Robotics, Alibaba, TaoBao - per the official Paparazzi wiki; it is not locally fabbable without SMT reflow capability.
  • OpenDroneMap processing is the dominant and most variable component of time-to-first-usable-map, and it is hardware-bound (RAM first). Direct field reports: 1,436 images on 96 GB RAM at ULTRA/ULTRA quality took nearly 57 hours; 3,000+ images will not process on 16 GB RAM; ODM's Lightning cloud service caps a task at 3,000 images / 128 GB RAM. A non-specialist team should expect the ODM run to take many hours to ~2+ days depending on dataset size, image count, and RAM - not minutes.
  • GCP placement is a genuine skill and equipment gate for a survey-grade map: the practical minimum is 5 GCPs (four corners + center), 30-60 cm high-contrast targets, surveyed with an RTK/PPK GNSS rover for 1-3 cm accuracy. Without GCPs, consumer drone GPS gives 1-3 m horizontal and up to ~10 m vertical error, which disqualifies the output for engineering/survey/GIS-overlay work. An RTK/PPK-equipped drone can skip physical GCPs entirely, but that shifts the skill/equipment cost to the drone.
  • Realistic per-operator regulatory/training cost in the US (Part 107): $175 knowledge test + $5 drone registration (min ~$180), plus roughly $149 for a test-prep course and 13+ hours of video study and a 60-question test, for a first-time-operator total of about $330. Renewal is free (online every 24 months). This is a one-time per-person cost, separate from the (free) Paparazzi/ODM software skills, which are self-taught from open docs and tutorials.
  • The 0.7-1.2 m / 0.7-2.1 m RMSE is setup-specific, not an inherent ODM limit: a GCP-validated study of the same OpenDroneMap stack (WebODM/NodeODM) measured 3D CE90 of 3.2-35 cm across three GNSS quality tiers (consumer, mid-range, RTK + survey-grade GCP) on 122-176 image datasets, and ODM's own documentation states that with GCPs absolute accuracy improves to ~2.5x GSD horizontal and ~4x GSD vertical (~17 cm at 7 cm GSD). Without GCPs, ODM output degrades to the on-board GNSS: standard-GPS absolute horizontal accuracy 2-6 m and vertical 3-4x worse per ODM documentation, and raw GNSS 3D CE90 in the devonrama study spanned 1.1 m (RTK) to 191 m (consumer camera GPS).
