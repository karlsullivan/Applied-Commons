Open-source (GPL-3.0, ~167 stars, active 2026) Python package for actigraphy data analysis, i.e. extracting sleep/wake structure from movement/actimeter recordings. The open analysis tool behind wearable movement-based sleep tracking; helps researchers, clinicians and developers.

Assembly

Tools: Python 3.9-3.12 interpreter (3.11 verified for v1.2.3; 3.9 verified for PyPI 1.2.2), Terminal (Linux/macOS) or Anaconda Prompt (Windows) with pip and venv, Miniconda + Java 8 (1.8) - only for the optional BBA/accelerometer .cwa conversion path
Skills: Basic command-line use (creating/activating a virtualenv, running pip install), Reading package documentation; running a short Python snippet, Optional: writing analysis code against the pyActigraphy API
Time: Core deployment 15-30 min for a first-time deployer (measured install: 33 s on Python 3.11 plus verification); optional BBA .cwa path adds 1-2 h (second env, Java 8); optional MESA sample data adds an undocumented NSRR access-request wait

  1. 1. Get a suitable CPython (3.9-3.12 for v1.2.3; 3.9-3.10 if using PyPI 1.2.2 with the BBA hard dependency) v1.2.3 setup.py declares python_requires '>=3.9,<3.13' and release notes state 3.9-3.12; the master README still says 'tested for python>=3.7 & <=3.9' for the PyPI release. In this run CPython 3.11.16 (host) and CPython 3.9.20 (python-build-standalone 20241016, sha256-verified) were used.
    Caution: Install Python per distro/upstream instructions so the system interpreter is not shadowed.
  2. 2. Create and activate a virtual environment README: 'python -m venv pyActiEnv' (Linux/macOS) or Miniconda 'conda create -n pyActi39 python=3.9' then 'conda activate pyActi39'. The venv contained the numba/numpy pin conflict hit in this run.
    Caution: Never pip-install into the system Python; the venv keeps system packages clean.
  3. 3. Install pyActigraphy Current v1.2.3 (GitHub tag, not yet on PyPI): 'pip install "pyActigraphy @ git+github.com; (git URL not documented upstream - used and verified in this run). PyPI release 1.2.2 per README: 'python -m pip install numba==0.57.1' then 'python -m pip install pyActigraphy' (older PyPI page says just 'pip3 install pyActigraphy'). Verified: 3.11+v1.2.3 resolved 43 packages in 33 s with no pin; 3.9+1.2.2 default-resolved numba 0.58.0 which failed at import against the accelerometer-pinned numpy 1.21.6, and the README numba==0.57.1 pin fixed it.
    Caution: If an import error mentions numba/numpy versions, apply the numba==0.57.1 pin rather than upgrading numpy (would break the accelerometer pin).
  4. 4. Verify the install (running-instance check) 'python -c "import pyActigraphy; print(pyActigraphy.__version__)"' - expect 1.2.3 (or 1.2.2); the import exercises numba-accelerated code. Verified for both versions in this run.
    Caution: None.
  5. 5. Acceptance test: quick-start on real data README quick start: 'rawAWD = pyActigraphy.io.read_raw_awd("/path/to/file.AWD"); rawAWD.IS()'. Upstream does not name a sample file; this pack fills that from the package itself: installed packages ship sample recordings under site-packages/pyActigraphy/tests/data/*.AWD (37 in 1.2.2, 43 in 1.2.3). Acceptance criterion: IS() returns a float. Verified values for example_01.AWD: 0.5073230866619975 (v1.2.3/3.11), 0.527656245354158 (v1.2.2/3.9).
    Caution: Actigraphy files are personal health recordings - read only from local paths you control; do not upload them to third parties.
  6. 6. (Optional) Tutorials Jupyter notebooks ship inside the package and in the repo docs/source/ (intro, batch, masking, sleep algorithms, state-transition, cosinor, FLM, MF-DFA, SSA, pyLight series). On Anaconda: launch anaconda-navigator and select the project environment, not base, before starting Jupyter.
    Caution: None.
  7. 7. (Optional) Convert raw Axivity AX3 / GENEActiv .cwa data via BBA pyActigraphy does not read .cwa directly (maintainer-confirmed in issue #143): build a second env - Miniconda, 'conda create -n accelerometer python=3.9 openjdk pip', 'pip install accelerometer' - then 'accProcess data/sample.cwa.gz' writes sample-summary.json + sample-timeSeries.csv.gz; analyze with 'pyActigraphy.io.read_raw_bba(path)' which infers the companion summary JSON from the file path.
    Caution: Java 8 (1.8) is a documented BBA minimum requirement; run accProcess on local-only files.
  8. 8. (Optional) Obtain a free sample dataset (MESA) NSRR MESA includes 7-day wrist-worn actigraphy for 2,237 participants; download requires a (free) NSRR data-access application with no documented turnaround time.
    Caution: NSRR data are covered by the access agreement - follow its terms.

Known gaps

What the original design does not document:

  • No minimum compute spec (CPU/RAM/disk) or reference price for the host is documented upstream; host cost left null.
  • pyActigraphy 1.2.2 (PyPI) hard-requires 'accelerometer>=6.2.2', but master setup.py and the read_raw_bba docs treat BBA as optional / not auto-installed - the released and head manifests disagree, so the exact install path for the biobank reader is not consistent in the docs.
  • BBA 'accelerometer' 7.5.0 pins Python <3.11 and old numpy/scipy/pandas/scikit-learn, which conflicts with pyActigraphy master (Python 3.9-3.12, pandas>=2.0.0,<3); a separate 3.9/3.10 env is implied for the raw-.cwa path but this conflict is not documented upstream.
  • CamNtech ActiWatch 8 / Actiwatch pricing could not be verified - the shop page is reCAPTCHA-gated; native-format actimeter cost is unverified.
  • GENEActiv (ActivInsights) price is quote-only ('Request a Quote'); the required USB cradle is also unpriced.
  • MESA's ActiWatch Spectrum (Philips Respironics) product URL returns 404 - the device appears discontinued; no current ActiWatch price found.
  • No requirements.txt / environment.yml / Dockerfile in the repo - the dependency list lives only in setup.py, and master has diverged from the v1.2.2 release by 108 commits.
  • The AX3 price is GBP ex-VAT from a UK store; no USD/other-region pricing or independent distributor listing was found.
  • UK Biobank raw AX3/GENEActiv data (application + participant consent) is a real data path but its access terms were not retrieved/verified, so it is noted as a path, not a priced source.
  • Deployment/runtime BOM and service costs are NOT documented upstream: the README gives pip/conda install steps but no explicit list of runtime costs (there are none for a local install: any laptop/server, ~US$0 marginal, no paid hosting).
  • setup.py at the master head (f1e1b4a) does not declare 'stochastic>=0.6.0' or 'accelerometer>=6.2.2', even though the latest PyPI release (1.2.2) requires both - the master metadata is stale relative to PyPI.
  • No PyPI release for the v1.2.3 / master head exists: the newest published release is 1.2.2 (2024-06-19), so 'pip install pyActigraphy' does not yet pull in the commit inspected here.
  • The two supplied bioRxiv links (2026.03.30.711342 and 2026.04.07.706161) could not be retrieved (web extract HTTP error and bioRxiv API 'no posts found'); their content and whether they introduce additional repos/files could not be verified and are therefore not cited.
  • The MESA (NSRR/sleepdata.org) and UK Biobank raw actigraphy datasets are access-gated (application required); no freely downloadable copy is linked from the package docs, so the raw-data path cannot be exercised end-to-end without an access grant.
  • The BBA 'accelerometer' dependency is licensed under a University of Oxford 'Academic Use Licence' (non-SPDX, academic-only), which is a compatibility/eligibility caveat for re-distributing a bundled deployment alongside pyActigraphy's GPL-3.0.
  • The Jupyter tutorial notebooks and the docs site reference sample data paths (e.g. test_sample.csv) but the docs do not provide a single, clearly-named 'sample dataset' download for a non-biobank (e.g. Actiwatch) deployment test; only per-format test files are bundled.
  • Stale/contradictory Python version guidance: master README 'tested for python>=3.7 & <=3.9' vs master setup.py '>=3.9,<3.13' vs v1.2.3 release notes '3.9, 3.10, 3.11, 3.12'; PyPI page carries an even older install snippet without the numba pin - no single authoritative page
  • v1.2.3 (2026-10-09) is tagged and marked Latest on GitHub but not yet published to PyPI (PyPI newest is 1.2.2, 2024-06-19); no documented install path for it (the git+URL used here is not in any upstream doc)
  • No documented deployment acceptance test / success criteria; the import + quick-start IS() check on a packaged sample file is assembled from the README quick start plus the observed tests/data contents
  • BBA version compatibility undocumented on both sides: 'accelerometer' 7.5.0 requires Python >=3.7,<3.11 (README minimums 'Python 3.7 to 3.10, Java 8 (1.8)') vs pyActigraphy v1.2.3 '>=3.9,<3.13' - the working 3.9-3.10 intersection with separate environments is inferred, not stated
  • PyPI 1.2.2 hard-depends on accelerometer>=6.2.2 whose pins (numpy==1.21.*, scikit-learn==1.0.2) break the default numba resolution on 3.9/3.10; the README numba==0.57.1 pin is the only workaround and is not explained as a conflict fix (v1.2.3 made the dependency optional via PR #161 but install docs were not updated)
  • No turnkey free sample actimeter file is pointed to for newcomers; the only named free dataset (MESA/NSRR) requires a data-access application with no documented turnaround (this pack fills the gap with the packaged tests/data/*.AWD files)
  • No data-privacy/security guidance for actigraphy recordings (personal health data); the offline/local-only nature holds in practice (verified) but is not stated in docs
  • CI configuration not verifiable from master: .gitlab-ci.yml returned 404 at the master branch root during this run, so the upstream-tested platform/version matrix is undocumented from master
  • BBA docs: the readthedocs install page repeatedly served stale cached content through the page extractor in this run; BBA install facts were taken from its GitHub README instead
  • No documented acceptance test / self-check: the README and docs give no 'how to verify a deployment works' procedure, no smoke-test script, and no documented known-answer targets a deployer can run without reading the test source - the only test procedure is the committed pytest suite, run by hand.
  • README quick-start numbers are stale and not reproducible from the bundled example files (see failure mode 2); upstream provides no reproducible quick-start target.
  • No PSG (clinical gold-standard) benchmark of pyActigraphy itself; the package has never been directly re-run against polysomnography.
  • No documented actimeter hardware bill of materials: the package is pure analysis software, and collecting the data requires a wrist actimeter (ActiGraph, CamNtech, Axivity, etc.) whose purchase cost and specs are outside the package and undocumented.
  • No documented compute/memory/disk requirements for large batch runs (SSA/DFA are flagged 'computationally intensive' but no size thresholds are given).
  • No guarantee that the released PyPI 1.2.2 wheel installs on any Python 3.11+ (no Python floor, unpinned deps); a deploy pack must pin the interpreter and dependencies itself.

Safety

Software-only build: no electrical/gas/pressure/structural/heat/water/food/chemical build hazards. Manage (1) personal-health-data privacy, (2) 'not-a-diagnosis' labelling of sleep outputs, and (3) the optional AX3 wearable's lithium battery and skin contact. No qualified-person step; not do-not-build.

HazardSeverityControls
Actigraphy and light-exposure recordings are personal health data (sleep, activity, light dose) identifying individuals. Field-trial deployments in homes/farms/villages will handle other people's health data; the pack has no systematic privacy/consent/anonymisation guidance (its own gap list concedes 'No data-privacy/security guidance for actigraphy recordings').mediumKeep recordings local-only and never upload them to third parties (pack step 5 already says this) - extend to every trial participant's data, not just the bundled samples.; Obtain informed consent/assent from each wearer before recording, and state who may access the data.; Anonymise or pseudonymise (as MESA does: 'Original dates have been removed', random BioLINCC ID) before any data leaves the site.; For the MESA/NSRR route, sign and follow the NSRR data-use agreement (pack step 8 notes this).; Define retention and deletion for trial recordings before the trial starts.
pyActigraphy computes sleep/wake detection (Cole-Kripke, Sadeh, Crespo, Roenneberg) and circadian metrics; in a home/village setting an individual's (or a child's) sleep output could be read as a clinical sleep-health judgement. The tool is a research analytics package, not a certified medical device, and the pack gives no 'not a diagnosis' boundary.lowLabel all output as a research/summary metric, not a clinical diagnosis.; Do not base clinical or employment/eligibility decisions on these outputs without independent clinical review.; State that actigraphy is a screening/research measure and that abnormal-looking values need a clinician, not the tool, for interpretation.
Optional hardware path: an Axivity AX3 (11 g, IPx8) is worn on the wrist for days (30-day battery at 12.5 Hz; MESA protocol = one week). Prolonged wrist wear of any actigraphy watch can cause skin irritation / allergic contact dermatitis, worsened by sweat. No wear guidance is in the pack or the BBA docs.lowInstruct wearers to remove the device regularly, check the skin, and clean/dry the band.; Do not wear over broken skin or an active rash; rotate wrist position.; Use a clean band/strap per wearer where possible; do not share bands between people.
Optional AX3 actimeter has a small sealed lithium battery charged over USB (the product 'excludes cable'). Standard lithium-cell fire/thermal-runaway risk, low for a small undamaged cell; hazard only if a damaged device is charged or a non-conforming cable is used.lowCharge only with the documented/supplied USB cable and a standard 5 V USB power source (no mains modification).; Do not charge a cracked/corroding/leaking unit; retire it if damaged.; Do not leave charging unattended for long periods or in hot/insulated locations; store away from high heat.; Dispose of end-of-life devices as a lithium-battery item, not general waste.
Software supply chain: the pack installs from 'git+github.com; (a tag not on PyPI and not documented upstream) and pulls ~43 packages from PyPI, plus Java 8 via conda. Unpinned, unhash-verified third-party code runs on the deployer's machine. The optional BBA 'accelerometer' path requires Java 8 (1.8) (confirmed on both the PyPI page and the GitHub README), which is end-of-life and no longer receives security updates. Evidence

The strongest findings from Applied Commons research on this project:

  • Latest release is v1.2.2, tagged and uploaded to PyPI on 19 Jun 2024 (a BBA file-reader hotfix over v1.2.1); prior releases: v1.2 (Mar 2023), v1.2.1 (Apr 2023), v1.1 (Jan 2023), v1.0 (Aug 2020).
  • CI is GitLab-based (the README badge points at gitlab.com/ghammad/pyActigraphy); there is no .github/ directory, so no GitHub Actions. CI runs one job on a single docker image python:3.7 that executes 'python -m pytest -vv --disable-pytest-warnings pyActigraphy/tests/'.
  • pyActigraphy v1.2.2 and master do NOT read raw Axivity .cwa or GENEActiv .bin files. Maintainer reply (issue #143, 2023-11-24): 'Directly reading .cwa files in pyActigraphy is not supported. The reason is that those .cwa files need to be resampled, calibrated, etc... there is already a fantastic package in python designed specifically to handle Axivity data: biobankAccelerometerAnalysis... pyActigraphy does read such files [the .csv files it produces]'. This answer is unchanged as of master.
  • The test suite in the repo spans 24 test modules (test_adat.py ... test_tal.py) containing 161 test functions; the suite is committed in pyActigraphy/tests/ with ~12 MB of fixture data.
  • The only Python version CI actually runs is 3.7 (docker image python:3.7), in both v1.2.2 and current master; no other interpreter is validated, so the effective supported matrix is untested beyond 3.7.
  • Documented supported input formats: ActiGraph wGT3X-BT; CamNtech Actiwatch 4/7/L(-Plus)/Mini/I(nsonmia)/T(emperature) and MotionWatch 8; Condor ActTrust 2; Daqtix Daqtometer; Respironics Actiwatch 2/Spectrum(+); MESA dataset; and BBA-converted Axivity AX3 and GENEActiv raw data via read_raw_bba. ActiGraph GT9X is NOT a listed supported format, and no Apple/Google/Oura (or any other wearable OS) format is documented.
  • The primary citation target, the PLOS Computational Biology companion paper (Hammad et al. 2021, DOI 10.1371/journal.pcbi.1009514), has a Semantic Scholar citationCount of 69 (influentialCitationCount 8), matching the question's 'cited by 69 papers'.
  • v1.2 (Zenodo record 7759250, 2023-03-22) added the BBA reader: 'new reader function for files generated by the accelerometer package that reads, calibrates and processes raw accelerometer data from Axivity AX3 and Activinsights GeneActiv devices (see pyActigraphy.io.read_raw_bba function)'. Verified in code (cloned repo): RawBBA reads a timeSeries.csv.gz produced by the external package, takes the 'acc' column (calibrated vector magnitude, mg per BBA data dictionary) plus light/sleep/sedentary/MVPA/MET columns and QC flags from summary.json (isCalibratedOnOwnData, isDSTCrossing); it contains no calibration, epoching, or count-conversion code, and a full-repo search finds no van Hees/count-conversion implementation anywhere in pyActigraphy.
