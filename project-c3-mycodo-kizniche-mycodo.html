Open-source (GPL v3) environmental monitoring and regulation system for Raspberry Pi / single-board computers that couples sensors (temperature, humidity, light, soil, etc.) to relays and PWM via PID and conditional logic to automate climate control in grow rooms, greenhouses and vertical farms. Self-hosted, no cloud required, with a full manual, API and an active community. The climate-control layer that pairs with any open vertical-farm structure, and the lowest-cost route to reliable year-round environment control. Maturity: mature and long-running - ~3,294 GitHub stars, 565 forks, in development since 2015, latest release 8.17.0.

Evidence

The strongest findings from Applied Commons research on this project:

  • Mycodo v8.17's README recommends Raspberry Pi 3, 4, or 5 and states Zero, 1, and 2 are no longer recommended; the docs home is stale and still lists 'any version: Zero, 1, 2, 3, or 4'. The README is authoritative.
  • Internet is a REQUIRED prerequisite for the install, not for operation: the README (v8.17.0) lists 'An active internet connection' under Prerequisites, and the install is curl -L kizniche.github.io | bash, which downloads packages. GitHub issue #1408 ('piwheels.org is offline. The installer dont work') confirms the installer depends on reaching upstream services. Practical consequence: install online once, then run offline.
  • The smallest SBC for the budget is the Raspberry Pi Zero 2 W: 120 mA / 600 mW at 5V idle on the stock image, ~74.5-75.5 mA (~375 mW) when tuned (GPU 16MB, HDMI off, LED off, 1 core); WiFi adds only ~11 mA; the 4-core@600MHz benchmark peaks at 449 mA (USB-port-safable), and full stress peaks 1.35-1.46 A.
  • Mycodo supports exactly this actuator set and natively power-accounting for it: every output channel has a 'Current (Amps)' field, and the Energy-Usage page computes kWh/cost from that draw (PWM outputs excluded from the calc). Supported outputs include GPIO on/off, I2C relay boards (Grove 4/8, SparkFun 4, Sequent 8), PCA9685 PWM for fans, stepper drivers (DRV8825/A4988/ULN2003) for vent openers, and peristaltic pumps.
  • No independently reproduced yield, spoilage-reduction, or nutritional outcome from a non-author Mycodo deployment exists in the public record (in any climate) as of this sweep. The peer-reviewed and grant-funded non-author deployments that do exist measured energy/runtime efficiency (Bhutan) and wastewater nutrient removal (New Jersey), not food outcomes, so a food-and-nutrition brief has no reproducible non-author quantitative food data to rely on.
  • Mycodo runs fully offline for normal post-install operation: the web UI (Flask web server), the control daemon, and measurement storage (local InfluxDB 1.x/2.x or bring-your-own) all run on the SBC itself, and the anonymous usage statistics it collects are opt-out-able in Settings. Nothing in normal operation requires an ongoing internet connection.
  • A Raspberry Pi has no real-time clock (RTC); with no NTP, a reboot can reset the clock to a wrong time, which corrupts Mycodo's time-series data. The README states 'Incorrect time can cause a number of issues with measurement storage and retrieval in a time-series database', and the maintainer (KyleGabriel) calls it 'disastrous if your measurements are being used for any crucial system, like growing plants or keeping animals alive'. Mitigation: add an RTC HAT (e.g. a DS3231) so the clock is maintained offline.
  • The only peer-reviewed non-author Mycodo deployment (Penjor et al. 2022, Bhutanese Journal of Agriculture; ARDC-Wengkhar, Bhutan, subtropical highland) compared automated vs manual operation over 70 days: manual runtime and energy use were 'more than 50% higher' than the automated system (Fig. 12; pumps 750W x2, exhaust fan 320W, oxygen pump 40W). Crops present were lettuce, strawberry and medicinal herbs, but the paper reports no yield, harvest-weight, spoilage, or nutritional figures, and pH/EC sensors were not tested. It supports an energy-efficiency claim only, not a food claim.
